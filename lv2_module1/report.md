## 문제2. 오차와 피드백 해성
실행A의 입력은
```bash
s 3 120 -90 # s P 3 속도 120 목표 -90
```
### 문제2-1. 실행 A의 초기·중간·마지막 시점에서 목표각과 현재각을 선택하고 오차 = 목표각 - 현재각을 계산하세요. 오차 크기의 변화를 설명하세요.
| 시점 | 목표각 | 현재각 | 오차 | 설명 |
| :--- | :---: | :---: | :---: | :--- |
| **초기** | -90.000 | 0.000 | -90.000 | - |
| **중간** | -90.000 | -117.422 | 27.422 | 최저각 도달, 오버슈트에서 가장 큰 오차발생지점 |
| **마지막** | -90.000 | -90.088 | 0.088 | 오버슈트에서 0.088의 오차까지 근점하여 거의 정지함 (아주 작은 단위로 떨림) |
> 시작각 0에서 -90이라는 목표까지 목표와 같은 부호로 오차가 있는 동안은 시작각과 목표각사이에 현재각이 존재하는 것이며, 목표와 오차의 부호가 달라지면 현재각이 목표각을 지나친 것. 현재각이 목표각을 지나쳐서 목표각과 가장 멀어졌을 때를 오버슈트라고 한다. 오차의 절대값이 크다는 것은 현재각과 목표각의 거리가 멀다는 것이며, p가 3이라 오차에 3을 곱한 것을 출력에 합산하여 최종 출력을 결정한다.

###  위치 측정값을 얻는 센서와 OpenCR까지의 통신 경로를 적으세요. 

>모터의 각을 측정하는 측정값은 모터의 엔코더 센서에서 얻으며, 이 과제의 경우 OpenCR이 모터와 TTL 통신 포트로 연결되어 OpenCR로 전송된다.

### 목표가 +30°이고 현재각이 +35°인 경우의 오차 부호와 양의 Kp에 의한 보정 방향을 설명하세요.

>목표가 30이고 현재각이 35이면
- 오차 = 목표각 - 현재각 으로 오차 = 30 - 35, 오차 = -5 이다.
- 오차가 -5 라는 것은 현재각이 목표각을 지나쳤고 보정하여 시작과 반대의 방향으로 이동해야 한다.
- 양의 Kp에 의한 보정 방향은 시작각에서 목표각 방향

### 3-2. 같은 경과시간 비교 (현재각·목표 초과 여부)
초과 = 현재각이 목표 −90°를 음(−)방향으로 통과한 상태. 차이 = A − B (현재각 기준).
| t_s | A 현재각 / 오차 / 초과 | B 현재각 / 오차 / 초과 | 차이·관찰 |
| :---: | :--- | :--- | :--- |
| 2.0 | 0.000 / −90.000 / 미초과 | 0.088 / −90.088 / 미초과 | 둘 다 u≒−119.5 포화, 출발 동일 |
| 3.0 | −47.900 / −42.100 / 미초과 | −46.318 / −43.682 / 미초과 | A가 약 1.6° 앞서감 |
| 4.0 | −116.104 / +26.104 / **초과** | −82.266 / −7.734 / 미초과 | 차이 최대 ≈33.8° |
| 5.0 | −93.691 / +3.691 / **초과** | −88.594 / −1.406 / 미초과 | A 복귀 임박, B 1.4° 남김 |
| 6.0 | −90.088 / +0.088 / 초과(잔류) | −89.648 / −0.352 / 미초과 | 둘 다 출력 정지(u=0) |
| 8.0 | −90.176 / +0.176 / 초과(잔류) | −89.648 / −0.352 / 미초과 | 정상상태 유지 |


### 3-3. 해석 (근거 포함)
- 초기(t 2.0–2.5)에는 두 실행이 거의 같은 궤적을 그린다. 근거: 요구 출력 p가 A −270, B −135로 모두 속도 상한 120을 초과하므로 최종 제어입력 u가 함께 약 −119.5에 포화되기 때문이다.
- 포화에서 벗어난 뒤(t 3.0~)에는 Kp 차이가 그대로 속도 차이로 나타난다. 근거: 같은 오차에서 A의 p가 B의 약 2배이므로(t 3.0에서 −126.3 vs −65.5) A가 더 빨리 목표에 도달해 3.5s에 통과하고, B는 같은 시각에 18°나 남는다.
- A는 관성으로 목표를 지나쳐 4.2s에 −117.422°까지 초과(27.422°)한 뒤 복귀하고, B는 감속이 일찍 걸려 단조롭게 접근하며 초과가 없다. 근거: A의 최대 실속도 104.4가 B의 82.4보다 크고, A만 오차 부호가 +로 반전된다.
- 정착 시각은 공히 약 5.4s이지만 최종 잔류오차 부호가 반대다(A +0.176°, B −0.352°). 근거: 이후 u=0으로 출력이 끊기는 출력 데드밴드 때문이며, 잔류오차가 엔코더 1틱(0.088°)의 정수배(2틱·4틱)라는 점과 초기 0/0.088° 지터도 같은 양자화 근거이다.
- 결론: 동일 조건에서 Kp 단일 변수가 응답을 갈랐다. Kp를 1.5→3.0으로 올리면 도달은 빨라지나 초과가 생기고, 낮추면 초과 없이 느리게 접근한다.

### 3-4. 게인 구분 및 I·D 역할
- 변경한 게인은 OpenCR 외곽 위치루프의 P게인이며 다이나믹셀 내부 게인이 아니다. 근거: 시리얼 명령 `s <Kp> ...`가 펌웨어의 `P SET Kp=...`로 반영되어 `p_deg_s = Kp×오차`가 계산되고 속도 상한으로 포화된 `u_deg_s`가 속도 명령으로 나가며, 다이나믹셀은 그 명령을 실행하고 엔코더 각을 되돌리는 역할만 하기 때문이다(다이나믹셀 Control Table의 내부 Position P Gain과는 다른 층위).
- I항의 역할: 중력·마찰 같은 지속 외란에 의한 정상상태 오차를 시간 누적으로 없애는 항이다.
- D항의 역할: 오차 변화율에 비례한 제동으로 오버슈트와 진동을 억제하는 감쇠 항이다.

## 4. 제어와 통신의 역할 해석
아래는 답안 작성을 위한 가상 기록의 일부이며 실제 실행 결과가 아닙니다. 설명용 인터페이스의 목표와 현재값 단위는 °입니다. 기존 8강의 RPM 속도 인터페이스와 구분하세요.

| 항목 | 설명용 조건·기록 |
|---|---|
| 제어 계산 | OpenCR에서 10ms마다 수행 |
| 상태 발행 | 100ms마다 수행 |
| 0.0초 | PC가 /motor/target에 30.0 발행 |
| 0.1초 | PC가 /motor/state에서 2.0 수신 |
| 0.5초 | PC가 /motor/state에서 12.0 수신 |
| 1.0초 | PC가 /motor/state에서 22.0 수신 |
| 2.0초 | PC가 /motor/state에서 29.0 수신 |

### 4-1. PC ROS2 노드·micro-ROS Agent·OpenCR·다이나믹셀을 연결한 구조도에 목표 전달과 측정값 반환 방향을 표시하세요.
- 목표 전달 방향
위 설명에서 /motor/target 30.0 을 전달한 목표라고 한다면
PC ROS2노드 -> Micro-ROS Agent -> openCR -> 다이나믹셀 방향으로 목표가 전달됩니다.
- 측정값 반환 방향
다이나믹셀 엔코더 -> openCR -> Micro-ROS Agent -> PC ROS2 노드 방향으로 측정값이 반환됩니다.

### 4-2. 목표와 상태를 보내고 받는 주체를 설명하세요.
주어진 내용으로는 PC ROS2 노드가 목표와 상태를 보내고 받는 주체가 됩니다.

### 4-3. 상태 발행 한 주기 동안 제어 계산이 몇 번 수행되는지 계산하고, 통신 단절 시 오래된 명령을 어떻게 처리할지 정책과 이유를 적으세요.
상태발행은 100ms마다 수행하며 제어 계산은 OpenCR에서 10ms마다 수행합니다.
따라서 상태발행 1회에 제어계산은 10회 실시합니다.
모터의 타겟은 실시간성 레벨이 Hard이며 통신단절로 인한 오래된 명령중에 마감을 넘긴 명령은 폐기되며 마감을 넘기지 않은 명령은 명령이 들어온 순서대로 수행합니다.
